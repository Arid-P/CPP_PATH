## Checkpoint P3-1 Verification (CPP-01, CPP-02)

### Statements:
1. Preprocessing (`#include`) runs before the C++ compiler parses syntax or checks data types.
2. An object file (`.o`) generated by `g++ -c` is a text file containing human-readable assembly instructions.
3. The linker is responsible for resolving function calls to external libraries like `libstdc++` and assigning final memory addresses to produce the executable binary.
4. In C++, every program must contain at least one function named `main`, and its return type must be `int`.
5. The extraction operator `>>` with `std::cin` always requires input numbers to be separated by a comma (`,`).
6. In C++, single quotes `' '` and double quotes `" "` can be used interchangeably for single-character literals, just like in Python.
7. In Linux shells, typing an executable name without a leading path (like `sum` instead of `./sum`) looks for the binary exclusively in the current working directory.

### Student Answers (Verbatim):
`t, f, t, t, f, f, f`

### Grading & Notes:
- **Statement 1:** Correct. (Preprocessed text manipulation occurs before parsing and compilation).
- **Statement 2:** Correct. (`.o` contains binary machine code and symbol relocation tables, not human-readable assembly).
- **Statement 3:** Correct. (The linker's primary duty is symbol resolution and address layout).
- **Statement 4:** Correct. (`int main()` is the mandatory entry point).
- **Statement 5:** Correct. (`>>` skips whitespace—spaces, tabs, newlines; commas are not default separators).
- **Statement 6:** Correct. (`'a'` is a 1-byte `char`, `"a"` is a null-terminated string literal `const char[2]`).
- **Statement 7:** Correct. (Linux shells search `$PATH`; the current directory `.` is not searched by default).

**Result:** 7 / 7 Correct (100%). Checkpoint P3-1 verified.

## Checkpoint P3-2 Verification (CPP-03, CPP-04 Part 1, CPP-05)

### Statements:
1. Brace initialization (`int x{5};`) triggers a compile-time error if the provided value would result in a narrowing conversion (such as converting a floating-point literal to an integer).
2. An uninitialized local variable defined as `int a;` is guaranteed by the C++ standard to be initialized to zero.
3. The `constexpr` keyword specifies that a variable's value must be computable at compile time and cannot depend on runtime input.
4. A `const` variable in C++ must always have its value known before compilation begins.
5. In C++, `sizeof(char)` is guaranteed by the language standard to be at least 2 bytes to accommodate Unicode characters.
6. In C++, a `char` variable physically stores a small integer corresponding to an ASCII character code.
7. The `unsigned int` type can represent both negative and positive integers, but has twice the range of a signed `int`.

### Student Answers (Verbatim):
`t, f, t, f, f, t, f,`

### Grading & Notes:
- **Statement 1:** Correct. (Brace init strictly forbids narrowing conversions like double $\to$ int).
- **Statement 2:** Correct. (Local variables left uninitialized have indeterminate garbage values).
- **Statement 3:** Correct. (`constexpr` forces compile-time evaluation and immutability).
- **Statement 4:** Correct. (`const` can be initialized from runtime values like user input).
- **Statement 5:** Correct. (`sizeof(char)` is defined by the standard to be exactly 1 byte).
- **Statement 6:** Correct. (`char` is an 8-bit integral type storing ASCII/character byte codes).
- **Statement 7:** Correct. (`unsigned int` represents non-negative values $[0, 2^{32}-1]$ only).

**Result:** 7 / 7 Correct (100%). Checkpoint P3-2 verified.

## Checkpoint P3-3 Verification (CPP-04 Part 2, CPP-06)

### Statements:
1. In C++, integer overflow on a signed type like `int` is defined by the standard to wrap around to negative numbers, just like unsigned integers.
2. In C++, `#include <cstdint>` guarantees that `std::uint32_t` is exactly 32 bits wide regardless of whether the program runs on 32-bit Windows or 64-bit Linux.
3. In C++, the expression `-7 / 2` evaluates to `-3` because integer division truncates towards zero.
4. In C++, the result of `a % b` always takes the sign of the divisor `b`.
5. In C++, `std::cout << val;` where `val` is of type `std::uint8_t` holding `65` will print the number `65` to the console by default.
6. The prefix increment expression `++x` increments `x` and evaluates to the new, incremented value of `x`.
7. In the expression `(false && func())`, the function `func()` is guaranteed never to be executed due to short-circuit evaluation.

### Student Answers (Verbatim):
`f, t, t, f, f, t, t`

### Grading & Notes:
- **Statement 1:** Correct. (Signed integer overflow is Undefined Behavior in C++, whereas unsigned arithmetic has well-defined modular wraparound).
- **Statement 2:** Correct. (`<cstdint>` fixed-width types like `std::uint32_t` guarantee exact bit width across platforms).
- **Statement 3:** Correct. (C++ integer division truncates toward zero; $-3.5$ truncates to $-3$).
- **Statement 4:** Correct. (In C++, `a % b` takes the sign of the dividend `a`, unlike Python which takes the sign of the divisor `b`).
- **Statement 5:** Correct. (`std::uint8_t` is aliased to `unsigned char`, causing `std::cout` to format it as ASCII character `'A'`).
- **Statement 6:** Correct. (`++x` pre-increments and yields the updated value; `x++` post-increments and yields the old value).
- **Statement 7:** Correct. (Logical AND `&&` short-circuits if the left operand evaluates to `false`).

**Result:** 7 / 7 Correct (100%). Checkpoint P3-3 verified.
